# Boards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Several boards per household, one on the wall; every game records its board; Stats filters by board and puts boards side by side; players, darts and boards in one Settings section.

**Architecture:** A `boards` table and `matches.board` column in `server/db.py`, served by `server/data_api.py`, synced offline-first by `web/sync.js` the way dart sets are. Stats take a `board` filter beside `darts`; the side-by-side figures are worked out in the app from the history (`web/stats.js`), grouped by board as they are by set.

**Tech Stack:** Python 3 / FastAPI / SQLite (server), plain ES modules (web), `pytest`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-22-boards-design.md`

## Global Constraints

- Board fields and limits as now: brand 40, model 40, notes 120 characters; bought a year 1900..this year (`BOARD_MAX`, `cleanBoard`). Same checks in Python and JS.
- Ids are made by the app, `^[\w-]{1,64}$` (`_ID`).
- An older app (no `board` in a match, no `/api/boards`) keeps working.
- Plain wording (see memory `ui-genuine-not-ai`); thresholds are `ENOUGH` in `web/stats.js`, not new numbers.
- Commit from a private git index (memory `concurrent-sessions-share-index`).

### Task 1: Boards in the database and the API

**Files:** Modify `server/db.py`, `server/data_api.py`. Test `tests/test_db.py`, `tests/test_data_api.py`.

**Produces:**
- Table `boards (id TEXT PRIMARY KEY, brand TEXT, model TEXT, bought INTEGER, notes TEXT, up INTEGER, down INTEGER, created INTEGER NOT NULL)`; `matches.board TEXT`.
- `prepare()`: adds `matches.board`; if `boards` is empty, makes the first board from `settings["settings"]["board"]` (or no details), `up` = first match's `started` or now, `down` NULL; sets every match's board to it; removes `board` from the stored settings.
- `clean_board(b: dict | None, year=None) -> dict | None` (same rules as `cleanBoard`).
- `list_boards() -> list[dict]` (`{id, brand, model, bought, notes, up, down, created}`, by `created, id`).
- `save_board(board_id: str, b: dict) -> dict`: upsert; `b` has the detail fields, `up`, `down`, `created`. When saved with `down` NULL, every other board with `down` NULL gets `down = b["up"]`.
- `delete_board(board_id) -> None`: `Invalid` if a match uses it or it is on the wall.
- `move_games(board_id, start: int | None, end: int | None, only: list[str | None] | None) -> int`: sets `board` on matches with `start <= started < end` (open where None) and, if `only` given, whose board is in `only` (None in it meaning no board). Returns the count. `NotFound` for an unknown board.
- `save_match`: `m["board"]` stored if a known board, else the board on the wall (or NULL); on update the stored board is kept (`COALESCE(matches.board, excluded.board)`). `export_match` includes `board`.
- Routes: `GET /api/boards`, `PUT /api/boards/{id}` (`BoardIn`), `DELETE /api/boards/{id}`, `POST /api/boards/{id}/games` (`MoveIn {start, end, only}` → `{moved}`). `MatchIn.board: str | None = None`.
